Baseline: upstream `2025-edition` commit `dc343f2683279ecbb13fab4e2fd778d7b162d287` and official JSON release SHA256 `7d749f6e2c39e6970e4997839dcf6e42fd281f3c2fae0171d2192bae8cfa4b51`. The 73 upstream YAML files in `src/yaml/` match the tag ZIP byte-for-byte. A complete structural comparison found no synset/lemma/definition/sense-list/declared-form difference between YAML and the official JSON ZIP. Source relations/examples and byte-identical release regeneration have not been compared.

`src/learning-glosses/` is a **sense-specific, additive extension in this same repository**, not a second authoritative repository. Each YAML file maps exactly one OEWN sense ID to a reviewed model-authored learning definition and source-definition hash; the upstream synset definition and lexeme files are untouched. This is necessary because OEWN's original definitions are shared by synset, while 210 of the staged shared synsets have different reviewed wording for different member senses. Replacing a shared synset definition with one member's simplification would change other words incorrectly.

Only 3,412 `decision: gloss` rows from 70 local batches are staged. The 88 reviewed `defer` rows keep original meanings and remain in source batch records; no artificial simplified text is added. Status is model-reviewed, not teacher/student validated. Original accepted batch files remain as audit lineage in the workspace and are not silently represented as approved human PRs.

See [LEARNING_GLOSS_WORKFLOW.md](LEARNING_GLOSS_WORKFLOW.md) for the one-file daily PR process and source-to-SQL build boundary. These YAML files are the single editable learning-gloss source. The `manifest.json` and `lineage/` directory record the initial 70-batch migration; daily editing does **not** require modifying their 3,412 individual hashes. Build tooling discovers current `*.yaml` files, validates each exact sense ID/path and original-definition hash, then generates a versioned SQLite query copy. GitHub PRs review individual YAML changes; SQL, published JSON, and the historical batch results are not edited by hand. The editorialStatus here records past same-model review, not authenticated teacher/student approval. The baseline is a genuine upstream `2025-edition` Git commit in a local clone; the user-owned public fork exists separately. No commit, push, PR or server deployment has been performed in this checkout.

The YAML source and JSON release use different formats but matching OEWN identities. After initial migration, maintain only this repository's YAML (upstream original plus extension) and regenerate SQL; do not hand-edit downloaded JSON or a deployed SQL database.
